# Working in this repository

These notes are for human contributors and automated agents alike. Follow the user's instructions and any more specific instructions that apply; this file describes what the project is and how to handle its local inputs safely.

## Project and evidence

Bayonetta 3 Recomp is a static ARM-to-C++ recompiler with a Horizon/NVN Vulkan runtime, targeting the main program of Bayonetta 3 version 1.2.0. The working tree has real combat measurements from Windows, Steam Deck, Android and macOS, and Windows chapter selection has reached Chapter 8. Read [the dated performance evidence](docs/PERFORMANCE.md) before describing status. No full playthrough is verified, and the Prologue story transition has a loading issue. Keep two things apart: existing project gameplay evidence, and what you personally reran. An old automation failure, a missing local input or the absence of a fresh end-to-end run does not make the project unplayable; by the same token, do not claim verification you did not perform.

When reproducing the project, start from the [copyable reproduction task](docs/AGENT-REPRODUCTION.md). Read [docs/BUILD.md](docs/BUILD.md) before changing preparation, build or test instructions, and check the scripts and their `--help` output, because defaults move. The standalone CMake tests need no game, but which tests are registered varies with host and dependencies. Record the exact commands, passes, skips and failures. A passing unit test does not prove gameplay. Some source comments point at historical analysis documents that are deliberately absent from this export; treat the available source and tests as the evidence rather than assuming those documents exist here.

## Private inputs and outputs

The game is not bundled; the user must supply it legally. Keep game files, keys, firmware, saves, generated source, binaries and shaders, game-derived analysis, logs and private configuration local. Do not put them in commits, reports or external services. Check proposed changes and attachments for private data and local paths: `.gitignore` is not a complete privacy boundary. Documentation screenshots are an exception to the absence of assets, not permission to publish them; image rights still need review.

CPU preparation through `tools/prepare_bayonetta3.py` runs on Linux, macOS and native Windows Python: it locks its output with `flock` or a Windows byte-range lock and links the RomFS and ExeFS with symlinks, or with directory junctions where Windows does not allow symlinks. Its tests pass on native Windows. A complete generation has been run on native Windows for the main program and for program 1 (the picture book's program): the generated code matches a Linux run of the same recompiler except for disassembly comments, and a main-program build from it reaches the title screen. Even `--inspect-only` writes analysis files, links and a manifest containing paths. Respect its locking and its refusal to overwrite output it does not own or that was modified. Do not remove, replace or bypass those protections to make a run succeed. The B3 shader tool needs a separately supplied compatible Kraken worker, Ryujinx shader sources and DLLs, and other tooling; a clean end-to-end generation is not verified. On Windows all of its steps have been run for both programs, with a worker built by LLVM-MinGW and `spirv-val` built from SPIRV-Tools source; the main program's shaders came out byte for byte identical to a set made on Linux. Use explicit paths instead of assuming another machine's defaults, and report missing inputs honestly.

## Changes and licensing

Keep edits scoped to the task, preserve other contributors' work, and avoid unrelated generated changes. Consult [docs/CONTRIBUTING.md](docs/CONTRIBUTING.md) and [docs/LICENSING.md](docs/LICENSING.md). Preserve source headers, copyright, attribution and license notices; the MIT terms in `LICENSE-MIT` coexist with the GPL-3.0-or-later combined-work terms in `LICENSE` and other third-party licenses. Check provenance before importing code or distributing combined artifacts. A source-code license never grants rights to game content or screenshots.
